# 路由卡格式

## 用户可见卡片

始终用简体中文，控制在一屏内。先给结论，再给理由：

```markdown
### 模型路由卡

- 处方作用域：<当前 Codex 对话或任务；一句话描述最终交付目标>
- 生命周期口径：<可预见最高阶段、最高复杂度与最高风险，不只写首轮轻量工作>
- 推荐配置：`<model>` · `<effort>`
- 相对额度：<低 / 中 / 高 / 很高；Spark 标注“独立池”>
- 风险下限：<low / medium / high / critical>
- 推荐理由：<两到三条与任务事实直接对应的理由>
- 重选参考：<仅在用户明确要求重选/改变额度偏好时，说明可验证的升降档条件>
- 失效条件：<当前运行时证实所选模型不可用或已退役>
- 额度不足：<缩小范围、分阶段、等待重置或额外 credits；高风险任务不静默降档>

请确认：**按推荐执行 / 优先节省额度 / 优先保证质量**。
```

一个新的 Codex 对话或任务首次进入实质工作时只显示这张卡。用户确认前，不开始需要该路由支撑的实质执行；后续消息只等待或解释原卡，不重新展示第二张。用户确认后，整个对话生命周期静默沿用，不因阶段、范围、风险、部署或归档恢复自动重问。

只有用户明确要求重选/改变额度偏好，或当前运行时证实所选模型不可用或已退役时，才显示一张替代卡。若当前只是回答“应该选哪个模型”，交付卡片即可。Skill 不能代替用户在 Codex 界面或运行时切换模型，也不能代替部署、发布、付款、删除、客户交付、隐私、安全或其他高风险审批。

## 机器可读结果

`scripts/route_model.py` 输出以下 JSON 字段：

| 字段 | 含义 |
|---|---|
| `model` | 推荐模型标识 |
| `effort` | 推荐推理档位 |
| `relative_quota` | 相对额度标签 |
| `risk_floor` | `low` / `medium` / `high` / `critical` |
| `reason_codes` | 触发推荐的稳定原因码数组 |
| `reasons` | 可直接转写到卡片的中文理由数组 |
| `upgrade_when` | 升档条件数组 |
| `downgrade_when` | 降档条件数组 |
| `quota_guardrail` | 额度不足时的保护说明 |
| `requires_user_confirmation` | 固定为 `true`；只用于首次卡或允许的替代卡，不表示每轮都要重问 |
| `alternatives` | 省额度与保质量两个可选配置 |

不要把脚本输出原样堆给用户。结合可预见完整生命周期把原因码翻译成简短、可核验的理由，并说明哪些字段是推断。脚本给出的 `upgrade_when` 和 `downgrade_when` 只是用户明确重选时的参考，不能据此自动弹卡。
